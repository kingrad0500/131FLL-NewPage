# Design Direction Study — Shamrock Run Fest

## 1. Purpose

This document evaluates the Shamrock Run Fest homepage as an interaction and visual-design reference for the Fort Lauderdale 13.1 rebuild. The objective is not to clone Shamrock’s branding or copy its page. The objective is to understand why it feels modern, energetic, and immersive, then translate those qualities into a distinct Fort Lauderdale experience.

Evidence inspected:

- Saved homepage HTML, approximately 1.1 MB.
- Complete companion asset folder.
- Five locally saved MP4 files.
- AVIF photography, sponsor graphics, and decorative artwork.
- Saved JavaScript/CSS bundles and responsive configuration.
- A 1920×1080 browser screenshot showing the opening hero.

The live domain remained blocked by the organization’s browser policy. The export is nevertheless detailed enough to verify the main component model, media strategy, type families, color system, breakpoints, and many animation timings.

## 2. What makes the reference feel modern

Shamrock Run Fest does not behave like a traditional information-heavy race website. It behaves more like a campaign landing page or event trailer:

- Motion begins immediately with a full-screen video-led hero.
- A continuously moving event-information ticker creates momentum before the main content.
- Navigation is deliberately minimal: logo plus a large outlined Menu control.
- The hero focuses on one emotional statement and one registration action.
- Typography is oversized and expressive rather than merely informational.
- Sections are built as distinct visual scenes instead of undifferentiated document bands.
- Repetition is used rhythmically: scrolling marquees, repeated distance cards, photography, and sponsor movement.
- Dark, warm neutrals make green accents and white typography feel vivid.
- Video, parallax, fade-ins, long transitions, and horizontal presentation all reinforce forward motion.

The central lesson is not “use more animations.” The lesson is to choreograph attention. Every section should have one purpose, one dominant visual idea, and one controlled transition into the next.

## 3. Verified technical observations

### 3.1 Platform and rendering model

- The export was generated by Wix/Thunderbolt.
- The runtime includes React and React DOM production bundles.
- Visible Wix components include:
  - Responsive menu container.
  - Responsive section/page-section system.
  - Responsive repeater.
  - Text marquee.
  - Media player/video box.
  - Image component.
  - Stylable buttons.
  - Header and footer sections.
  - Media controls and overlay controls.
- The implementation uses component variants and many generated element-level transitions.

We should not reproduce Wix’s generated architecture. It is extremely verbose. The Fort Lauderdale build should express the same ideas with a small, intentional component system.

### 3.2 Responsive thresholds

The saved CSS repeatedly defines responsive ranges around:

- 320–750 px.
- 320–1000 px.
- Desktop above approximately 1000 px.

This suggests three primary experiences:

- Mobile.
- Tablet/small desktop.
- Large desktop.

The new site can use more conventional content-driven breakpoints, but should preserve three genuinely designed modes rather than merely scaling the desktop version down.

### 3.3 Motion and transition evidence

The export contains substantial motion configuration:

- Hundreds of transition and animation references.
- Multiple parallax/background-motion references.
- Sticky-positioned controls.
- A dedicated Text Marquee component.
- Horizontal overflow/scroll structures.
- Repeater-based card collections.
- Fade-in animations using approximately 1,200 ms timing.
- Several long approximately 10-second variant transitions, likely associated with rotating media/card states.
- Button transitions around 200 ms.
- Menu/submenu transitions around 330–500 ms.
- Video poster fade of approximately 1,600 ms.
- Video roll-in/scale behavior around 250–500 ms.
- Page transition styles include horizontal slide, vertical slide, and out/in fades with custom cubic-bezier easing.
- Reduced-motion handling is present for page transitions and media behavior.

This confirms that the polished feeling is produced by multiple motion layers:

1. Ambient motion: looping video and marquees.
2. Scroll motion: reveals, parallax, and sticky scenes.
3. Component motion: sliders/repeaters and card transitions.
4. Micro-motion: buttons, menu, media controls, and hover states.

### 3.4 Local media package

The export contains:

- Five MP4 clips ranging from roughly 3 MB to 21 MB.
- Numerous AVIF images.
- Sponsor-logo assets.
- Decorative flower and group graphics.
- Dedicated media-player code.

The media strategy favors modern compressed formats and uses video as a core storytelling layer—not as a decorative afterthought.

### 3.5 Typography

The saved styles reference:

- Neue Haas Display Roman.
- Neue Haas Display Medium.
- Neue Haas Display Black.
- Gazzetta Variable.
- Cofo Peshka Variable.
- Supporting Helvetica Neue/Wix fallback faces.

Observed hierarchy:

- Strong grotesk/neo-grotesk sans serif for navigation, labels, prices, and structural headings.
- Expressive italic/display lettering for the hero phrase “Portland’s Luckiest Miles”.
- Very heavy display weights for large section headlines.
- Typography changes personality across layers while remaining disciplined.

For Fort Lauderdale:

- Use one modern grotesk family for utility and structure.
- Add one expressive display face for emotional/event language.
- Avoid using the expressive face for long paragraphs or interface controls.
- Build a fluid type scale with `clamp()` rather than dozens of fixed values.

### 3.6 Color system

Frequently occurring verified colors:

| Color | Reference use |
|---|---|
| `#151411` | Primary near-black/warm black |
| `#E4DCD5` | Warm off-white/beige canvas and button background |
| `#FFFFFF` | Hero copy and contrast text |
| `#1BC593` | Bright mint/green accent |
| `#0D5F47` | Deep green |
| `#F68D3D` | Warm orange accent |

The hero registration button uses a green gradient approximately from `#1BC593` to `#0D5F47`, a 2 px bright-green border, and a 50 px pill radius.

Fort Lauderdale should not inherit the Shamrock green palette. It should translate the contrast system:

- Warm/dark photographic foundations.
- Fort Lauderdale navy as the anchoring dark color.
- Event yellow as the high-energy accent.
- Aqua/turquoise as a coastal secondary accent.
- Warm coral/orange used sparingly for festival energy.
- Soft sand/off-white instead of sterile white for selected sections.

## 4. Opening viewport anatomy

The observed 1920×1080 composition contains:

### 4.1 Scrolling announcement ticker

- Full-width green strip at the top.
- Large uppercase white text.
- Repeated content:
  - Date.
  - Portland, OR.
  - Available distances.
- Dot separators and long right-arrow glyphs.
- Content repeats beyond viewport edges, clearly communicating continuous horizontal motion.

Why it works:

- Delivers essential event information instantly.
- Makes the site feel alive before any user interaction.
- Creates a strong visual boundary above the hero.

Fort Lauderdale translation:

- Navy or bright-yellow ticker.
- Repeat “NOVEMBER 8, 2026 • FORT LAUDERDALE, FL • 13.1 / RELAY / 10K / 5K”.
- Use CSS transform animation with duplicated content.
- Pause on hover/focus.
- Disable movement under `prefers-reduced-motion`.
- Do not make the ticker the only place containing essential information.

### 4.2 Minimal overlay header

- Wordmark at the upper left in white.
- “Presented by Toyota” lockup adjacent.
- Large outlined pill Menu button at upper right.
- Header sits over the video hero rather than occupying a separate white bar.

Why it works:

- Keeps the hero cinematic.
- Reduces cognitive load.
- Makes navigation feel intentional instead of crowded.

Fort Lauderdale translation:

- Use the event logo in white or navy/yellow depending on hero contrast.
- Use a compact “Menu” pill or menu icon/label combination.
- Registration remains independently visible as the primary CTA.
- Sponsor lockup must be subordinate to the event identity.
- Header should become solid or blurred when scrolling over light content.

### 4.3 Full-screen video hero

- Hero consumes nearly the entire initial viewport.
- Background appears to be a looping event/lifestyle video.
- A dark red/warm overlay ensures text readability.
- Content is centered vertically and horizontally.
- Decorative running shamrock icon sits above the headline.
- Main expressive headline: “Portland’s Luckiest Miles”.
- Large green pill CTA: “Register now”.

Why it works:

- Emotion precedes logistics.
- One headline and one CTA create a clear decision.
- The video supplies human energy without competing text blocks.

Fort Lauderdale translation:

- Full-screen or 85–95 `svh` video hero.
- Coastal race footage: sunrise, A1A, ocean, palms, cheering, finish line, festival.
- Navy-to-transparent or sunset-toned gradient overlay.
- Emotional headline distinct from the old site’s purely promotional banner.
- One primary registration CTA and one lower-priority “Explore the races” link.
- Include a poster image and never autoplay audio.

## 5. Homepage content and component inventory

The extracted document text reveals the following homepage structure after the hero.

### 5.1 Countdown scene

- Heading: “COUNTDOWN”.
- Supporting line: “TO RACE DAY”.
- Likely animated numeric countdown.

Fort Lauderdale idea:

- Four values: days, hours, minutes, seconds.
- Large outlined or split-flap-inspired numerals.
- Run only client-side after hydration to avoid mismatches.
- Provide a static date sentence for assistive technology.
- Stop the timer cleanly when the event begins.

### 5.2 Editorial introduction

- Heading/question: “WHY RUN SHAMROCK RUN FEST?”
- A large narrative paragraph.
- Follow-up statement about nearly fifty years of tradition.

Fort Lauderdale idea:

- Replace generic race marketing with a short editorial story:
  - Sunrise on A1A.
  - Oceanfront miles.
  - Las Olas.
  - Post-race festival.
- Use staggered line reveal or masked text entrance, but keep the text selectable and semantic.
- Keep the paragraph measure narrow.

### 5.3 Benefit/story feature sequence

Extracted themes:

- Portland’s Longest Running Tradition.
- Irish Charm.
- Community Connection.
- Iconic Pacific Northwest Route.
- A Race For Every Pace.
- A Celebration Fit for St. Paddy.

This likely forms a scroll-driven set of image/text scenes or cards.

Fort Lauderdale equivalents:

- Oceanfront Miles.
- Las Olas Energy.
- A Race for Every Pace.
- A Citywide Running Festival.
- South Florida Community.
- Finish-Line Celebration.

Recommended treatment:

- Sticky media panel on one side.
- Copy panels scroll on the other.
- Active copy changes the media, gradient, or short video.

- Never trap scrolling or require precision gestures.

### 5.4 Five-distance showcase

Extracted items:

- 13.1.
- 8K.
- 5K.
- 5K Walk.
- Leprechaun Lap.

This is likely the visually rich slider/repeater noted by the user.

Fort Lauderdale equivalent:

- 13.1.
- Relay.
- 10K.
- 5K if current.
- Youth/family race only if the event offers one.

Recommended interaction:

- Keyboard-accessible previous/next controls.
- Snap points for predictable movement.
- Progress indicator and meaningful slide labels.
- Media shifts or scales subtly as each card becomes active.
- Mobile supports native horizontal swipe with CSS scroll snap.
- Pricing should be data-driven and omitted when unavailable.

### 5.5 Partner marquee

Fort Lauderdale translation:

- Pause on hover and focus.
- Do not distort logos to identical dimensions; normalize optical height.
- Provide a static wrapped layout under reduced motion.

## 6. Proposed Fort Lauderdale visual direction

### Concept: “Sunrise to Finish Line”

Use the city’s defining visual assets—ocean light, palms, A1A, Las Olas, bright athletic color, and festival energy—to create a modern coastal race experience.

### Core mood

- Fast but not aggressive.
- Warm, coastal, optimistic.
- Premium event photography.
- Clear athletic information.
- Festival energy layered over a credible race experience.

### Suggested palette

| Role | Suggested direction |
|---|---|
| Deep anchor | Fort Lauderdale navy |
| Primary action | Event yellow |
| Coastal secondary | Aqua/turquoise |
| Warm highlight | Coral/orange |
| Light canvas | Warm sand/off-white |
| Dark canvas | Near-black navy |

### Suggested typography

- Structural grotesk: Neue Haas-like or another licensed modern grotesk.
- Display accent: energetic italic or hand-drawn script with excellent legibility.
- Numerical face: bold condensed display for countdowns, distances, and dates.
- Body: neutral readable sans serif.

The expressive display face must be used selectively. Its job is to create memorability, not to become the interface.

## 7. Motion system for the new site

### 7.1 Principles

- Motion communicates hierarchy and direction.
- Scroll progress should reveal content, not conceal it.
- Every animated section must also work when animation is disabled.
- Limit simultaneous movement.
- Prefer transforms and opacity.
- Avoid scroll-jacking.
- Avoid animating long paragraphs word by word.
- Maintain 60 fps on typical mobile devices.

### 7.2 Motion tiers

#### Tier 1 — Ambient

- Hero video.
- Event-detail ticker.
- Supporting sponsor marquee.

These may loop, but should move slowly and pause appropriately.

#### Tier 2 — Scroll choreography

- Masked headline reveal.
- Image parallax limited to approximately 4–8% travel.
- Sticky story sequence.
- Distance-card horizontal progress.
- Section background/color transitions.

#### Tier 3 — Interaction

- Menu open/close.
- Card hover/focus.
- Button arrow/label movement.
- Slider controls.
- Video play/pause and mute controls where applicable.

### 7.3 Timing recommendations

- Button/hover: 160–240 ms.
- Menu: 350–500 ms.
- Section entrance: 600–900 ms.
- Editorial line reveal: 700–1,000 ms.
- Media crossfade: 600–1,200 ms.
- Marquee: duration based on content width, usually 20–45 seconds per loop.
- Avoid the reference’s generated 10-second transitions unless they are intentional slow ambient crossfades.

### 7.4 Easing

Recommended base easings:

- Standard: `cubic-bezier(.22, 1, .36, 1)`.
- Emphasized: `cubic-bezier(.16, 1, .3, 1)`.
- Menu slide: `cubic-bezier(.87, 0, .13, 1)`.

Use a small token set rather than unique easing for every component.

## 8. Performance architecture

The reference export contains multiple videos and a very large generated runtime. Our implementation should feel equally rich with less cost.

Requirements:

- Use AVIF/WebP responsive images.
- Supply correctly sized `srcset` candidates.
- Use poster images for all videos.
- Keep hero video short, muted, looping, and optimized.
- Prefer one hero video active at a time.
- Defer below-the-fold videos until near the viewport.
- Pause videos when not visible.
- Lazy-load sponsor and card imagery.
- Reserve intrinsic aspect ratios to prevent layout shifts.
- Avoid loading animation libraries for pages that do not use them.
- Use CSS for marquees, hover states, and simple reveals.
- Use a small scroll-animation layer only for sticky timelines and synchronized sequences.
- Test low-power mobile devices and Safari.

Provisional budgets:

- Initial JavaScript: under 180 KB compressed where practical.
- Initial critical image/poster: under 300 KB.
- Hero video: target under 6–8 MB with adaptive fallback.
- Largest Contentful Paint: under 2.5 seconds on a representative mobile connection.
- Cumulative Layout Shift: under 0.1.

## 9. Accessibility and reduced motion

The final effect must not depend on motion.

- Respect `prefers-reduced-motion`.
- Replace video autoplay with a static poster when reduced motion is requested.
- Stop marquee movement and display a wrapped static list.
- Convert scroll-driven transformations to fully visible static content.
- Keep slider cards reachable by keyboard.
- Provide visible focus states.
- Announce slider position without excessive live-region chatter.
- Give video controls accessible names.
- Ensure overlay contrast remains sufficient for every video frame.
- Avoid flashing cuts and rapid luminance changes.
- Preserve normal document reading order beneath sticky/pinned layouts.
- Provide skip-to-content.

## 10. How `agents.md` should guide the final build

The existing `agents.md` should gain a Shamrock-inspired experience section containing enforceable rules rather than vague adjectives.

### Required additions

#### Experience goal

“Create a cinematic coastal race experience that feels active from the first viewport while keeping registration and race information immediately understandable.”

#### Non-negotiable homepage sequence

1. Event-information ticker.
2. Overlay header.
3. Full-height media hero.
4. Primary registration CTA.
5. Countdown.
6. Editorial event story.
7. Scroll-driven Fort Lauderdale benefit sequence.
8. Race-distance slider.
9. Festival/social proof.
10. Sponsor marquee/showcase.
11. Conversion footer.

#### Component rules

- `EventTicker` uses duplicated content and reduced-motion fallback.
- `MediaHero` requires video, poster, overlay, focal point, and static fallback.
- `OverlayHeader` changes theme after leaving the hero.
- `StoryScroller` becomes stacked content on mobile/reduced motion.
- `DistanceRail` supports pointer, keyboard, buttons, and native mobile swipe.
- `SponsorMarquee` pauses and has a static fallback.
- `FullScreenMenu` traps and restores focus.
- `MotionProvider` centralizes reduced-motion state and animation tokens.

#### Content rules

- One emotional hero statement.
- One dominant hero CTA.
- Never place important copy only inside video or imagery.
- Every homepage scene has a single communication objective.
- Keep logistical detail on supporting pages; use concise summaries and links on the homepage.
- Do not reproduce outdated years or source-site content defects.

#### Motion rules

- No scroll-jacking.
- No animation may block navigation or content access.
- Use no more than one dominant scroll effect per viewport.
- All motion needs a reduced-motion version.
- Animations must use transform/opacity unless a measured exception is approved.
- Avoid stagger chains longer than approximately 500 ms.
- Test animation with keyboard navigation and browser zoom.

#### QA rules

- Test 1440, 1024, 768, 390, and 320 px.
- Test with reduced motion.
- Test with video blocked.
- Test slow network and CPU throttling.
- Test keyboard-only navigation.
- Test Safari/iOS autoplay behavior.
- Verify no horizontal overflow except inside explicitly labeled rails.
- Verify sticky sections release correctly.
- Verify menu focus restoration.
- Verify paused/offscreen video behavior.

## 12. Recommended build sequence

1. Confirm Fort Lauderdale brand assets, current event data, and final race distances.
2. Create the design-token foundation.
3. Build the static semantic homepage with no animation.
4. Add the overlay header and accessible full-screen menu.
5. Optimize and integrate the hero video/poster.
6. Add ticker and countdown.
7. Build the distance rail with native scroll snap first.
8. Build the story sequence as a normal stack.
9. Enhance the story sequence into a sticky scroll experience on capable desktop layouts.
10. Add sponsor movement and remaining micro-interactions.
11. Implement reduced-motion and media-failure paths.
12. Run performance, accessibility, and responsive QA.

## 13. What to borrow and what not to borrow

### Borrow

- Cinematic first viewport.
- Minimal overlay navigation.
- Moving event-information ticker.
- Strong headline/CTA hierarchy.
- Multi-font editorial system.
- Scene-based storytelling.
- Horizontal distance showcase.
- Sponsor movement.
- Layered but controlled motion.
- Warm dark/light contrast.

### Do not borrow

- Shamrock iconography or Irish visual language.
- Portland-specific copy.
- Green as the primary Fort Lauderdale brand color.
- Generated Wix component complexity.
- Excessively long or duplicated transitions.
- Any inaccessible scroll trap.
- Any slider requiring a mouse.
- Large media payloads without visibility control.

## 14. Final direction

The old Fort Lauderdale site communicates information but feels assembled as static bands. The Shamrock reference demonstrates how the same event content can become an unfolding experience.

The recommended final product should combine:

- The Fort Lauderdale site’s complete race information and sponsor visibility.
- Shamrock’s cinematic pacing and confident hierarchy.
- A simpler, custom component architecture.
- Coastal Fort Lauderdale art direction.
- Progressive enhancement so content remains excellent without video or animation.

The target is not “a webpage with cool effects.” It is a race story whose motion supports registration, anticipation, and discovery.
